# 需要团队人工完成的工作

当前数据集核对照片和表格随v0.1.0报告发布包提供；新采集的私有资料仍保留在本地工作区。公开源码包含空采集模板及评估工具。

## 当前优先事项

1. 打开 `reports/review/comparison_16.jpg` 并结合编号原图，填写 `review.txt` 的人工读数和核验人。这里的“数据集标注”和“预测”都不是本次人工核验结果。
2. 先核查高倍率错位、指针接近进位、反光和模糊图片，记录真实读数、倍率及争议原因。不要仅凭模型预测修改标签。建议两人先独立读表，存在分歧时共同复核。
3. 如果发现数据集标注错误，保留原标签，另存修订清单及核验人。当前划分和模型绑定了清单哈希，不能直接修改 `data/manifest.json`；后续应建立新版本数据并重新记录评估。
4. 记录团队分工、采集/标注过程和实验结果，用于展示团队研发过程。未超过 baseline 的实验同样保留结果，避免只展示最好的分数。

读表时先确认每个盘的倍率和实际递增方向，按尚未到达下一数字时读前一数字的规则判断，结合低位进位复核；遮挡、正压刻度和进位争议应回看清晰原图或现场，不能由 AI 代替人工确认。

## 新照片采集模板

这部分用于补充真实独立评估，目前没有这类照片，不产生独立准确率。仅换角度重拍训练中同一块实体水表，不能称为“未见实体水表”测试。

- 采集全指针型实体水表，每块表固定一个 `meter_id`，记录拍摄时间、场景、光照、距离、反光和倾斜。可先做少量表的探索性试点，覆盖更多表型后再扩大；不要凭照片总数声称独立实体数量充足。
- 真值先由两人直接读图或现场读表，`reading` 用十进制字符串、最多 4 位小数。先完成真值与纳入规则，再查看预测；无法判读的情况提前记录，避免按预测结果筛选图片。
- 新照片放在 `data/collection/private/images/`。将 `sample.example.json` 的字段复制到 `independent.json` 的 `samples` 中，替换全部示例；照片路径相对于 `independent.json`。
- 人工确认采集对象未进入研发/训练，并冻结清单后，再填写确认人、将两项确认设为 true。这些字段是采集事实声明，程序不能自动证明实体独立性。WMeter5K 的实体身份并不齐全，因此采集来源仍需人工核实。

```powershell
.\.venv-wmeter\Scripts\python.exe evaluate_external.py data/collection/independent.json --output reports/independent_v1 --device cuda:0
```

评估工具要求人工真值和两位核验人，拒绝与已知 WMeter5K 暴露图片相同 SHA256 的图片及批内重复，输出总准确率、每块表结果和按表平均。重编码、近重复和实体身份还需要人工检查。空模板会直接报错，不生成虚假的评估分数。

若使用该批结果调整模型，这批数据就成为开发数据；最终独立测试需要另采新数据。
